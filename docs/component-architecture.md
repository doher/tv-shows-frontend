# Архитектура компонентов

Правила применяются ко всем React-компонентам, включая вложенные, общие
и UI-kit, а также к бизнес-сценариям.

## Структура компонента

Каждый компонент размещай в отдельной папке с именем компонента в PascalCase.
View и CSS Module обязательны. Называй их по имени компонента, например
`Button.tsx` и `Button.module.css`. Имя экспортируемого компонента
совпадает с именем папки.

Если у компонента есть собственная логика, добавь `logic/usePresenter.ts`.
В `logic/` также размещай вспомогательные хуки и обычные функции presenter
для работы с интерфейсом, например управления фокусом, форматирования
данных для View или заполнения поля промокода из URL. Проверку условий
акции и расчёт скидки выполняет [бизнес-сценарий](#бизнес-сценарии).

Держи файлы с логикой небольшими. По возможности ограничивай каждый файл
одной самостоятельной задачей. Если в `logic/` накапливаются группы файлов
для разных частей интерфейса, собирай их по назначению, например в
`search/` и `favorites/`.

Типы и интерфейсы компонента размещай в `types.ts` в корне его папки.

## View и presenter

- View возвращает JSX на основе props и результата собственного
  `usePresenter`, если он есть.
- Компонент и его вспомогательные файлы используют только его собственный
  `usePresenter`.
- Во View разрешены импорты `usePresenter`, CSS Module, подкомпонентов,
  типов для JSX и props, а также `observer` для подписки на состояние MobX.
- В `usePresenter` управляй состоянием и эффектами интерфейса,
  обрабатывай события, готовь данные для View и вызывай
  [бизнес-сценарии](#бизнес-сценарии).
- Во View допустима логика отображения, включая `.map()` для вывода списков,
  условный JSX и выбор CSS-классов.

Логику интерфейса, нужную нескольким компонентам, выноси в общий хук
или функцию.

## Сторы MobX

В сторе храни наблюдаемое состояние, а производные значения вычисляй
в геттерах. Связанные поля обновляй одним действием MobX. Если запись
зависит от текущего состояния стора, проверь его в том же действии.

Порядок запросов определяй в [бизнес-сценарии](#бизнес-сценарии).
Управляй отменой запросов вне стора. Если запрос привязан к жизненному
циклу компонента, отменяй его при очистке эффекта.

## Бизнес-сценарии

Бизнес-сценарий реализуй как `task` — обычную функцию, которую можно
вызвать без React. Начинай имя функции с глагола, который описывает
действие, например `submitOrder`.

В `task` размещай проверки и вычисления по правилам предметной области,
а также обращения к внешним системам в рамках сценария. Если сценарию
нужен стор, обращайся к нему напрямую через его публичный API.

Общие технические функции для нескольких сценариев, например сборку URL
API, размещай за пределами `tasks/`.

Для серверного сценария размещай бизнес-правила на сервере. На фронтенде
`task` вызывает API и возвращает результат сценария.

Сценарий, который вызывает логика одного компонента, размещай в его
`logic/tasks/`. При передаче готового обработчика через props потребителем
сценария остаётся компонент, в логике которого определён вызов.
Для общих сценариев применяй [правило области использования](#общие-компоненты-и-сценарии).

Если реализация занимает один файл, назови его по имени функции, например
`submitOrder.ts`. Если сценарию нужны вспомогательные файлы, помести
реализацию в папку с именем функции. Используй `index.ts` этой папки
как точку входа для потребителей сценария и экспортируй из него функцию.
Вспомогательные модули используй внутри сценария. Правило именования
и экспорта одинаково для локальных и общих сценариев.

## Вложенные компоненты

Подкомпонент, используемый одним родителем, размещай внутри папки родителя
в собственной папке.

## Общие компоненты и сценарии

Если один компонент или сценарий используют два или более компонентов,
выбирай ближайший общий родительский каталог потребителей. Общий компонент
размещай там в `components/`, общий сценарий — в `tasks/`.

Для модулей в `P/components/` и `P/tasks/` разрешены потребители
в каталоге `P` и во всём его поддереве. Это ограничение действует также
при реэкспортах.

В примере `useCartForm.ts` управляет полями формы `Cart`. При оформлении
заказа `usePresenter` вызывает `submitOrder` и передаёт состояние отправки
во View. `OrderSummary` также вызывает `submitOrder` из своего `usePresenter`.
Оба компонента используют `OrderTotal`.

`submitOrder/index.ts` экспортирует сценарий, а `buildOrderPayload.ts` готовит
данные для отправки внутри него. Только логика `Cart` вызывает `removeCartItem`.
Вложенный `CartItem` получает готовый обработчик удаления через props.

```text
Checkout/
├── Checkout.tsx
├── Checkout.module.css
├── Cart/
│   ├── Cart.tsx
│   ├── Cart.module.css
│   ├── logic/
│   │   ├── usePresenter.ts
│   │   ├── useCartForm.ts
│   │   └── tasks/
│   │       └── removeCartItem.ts
│   └── CartItem/
│       ├── CartItem.tsx
│       ├── types.ts
│       └── CartItem.module.css
├── OrderSummary/
│   ├── OrderSummary.tsx
│   ├── OrderSummary.module.css
│   └── logic/
│       └── usePresenter.ts
├── components/
│   └── OrderTotal/
│       ├── OrderTotal.tsx
│       ├── types.ts
│       └── OrderTotal.module.css
└── tasks/
    └── submitOrder/
        ├── index.ts
        └── buildOrderPayload.ts
```

## UI-kit

Общие UI-компоненты приложения размещай в `src/ui-kit`.
Они доступны компонентам во всём дереве `src`.
